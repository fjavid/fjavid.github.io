Prefix caching under prompt mutations

February 2026 · github.com/fjavid/prefix_caching

Prefix caching reuses precomputed KV blocks for shared prompt prefixes, which lowers prefill work and usually helps time-to-first-token (TTFT) and throughput. Real traffic rarely repeats prompts exactly: retrieved chunks differ, parameters and units change, templates drift. This project is a benchmark I am putting together to measure how that kind of variation affects cache reuse and serving behavior—starting from two workload families, RAG-style prompts and structured scientific prompts, with a clear split between meaning-preserving mutations (reorder, format, noise) and meaning-changing ones (new parameters, different evidence, constraint flips).

The repository wires up controlled mutation generation, overlap metrics, validation, and severity scoring so each prompt pair is labeled before it hits the inference harness. Later stages add serving runs with and without caching, plus simple prompt-organization baselines (e.g. stable prefix first, volatile tail). There are no benchmark plots or tables on this page yet; I will add results here once the runs are ready.

Everything lives in github.com/fjavid/prefix_caching, including a longer project_description.md on goals and methodology.
